# Проверка серверного хранения Klar — 29.10.2026

## Подготовка Neon

29.10.2026 по команде пользователя подготовлена облачная база Neon. Все пять миграций применены через `migrate deploy`; повторный запуск сообщил об отсутствии ожидающих миграций. Seed завершён, фактические количества проверены запросами к Neon: 2000 слов и 2000 переводов, 71 глагол, 81 набор существительных, 1588 заданий с предложениями, 228 видеоуроков, 8 мини-уроков, 48 шагов, 5904 версии упражнений, 7164 допустимых ответа, 4047 ступеней достижений. Строки подключения находятся только в игнорируемом `.env.neon.local`; локальный `.env` сохранён.

Seed использует не более пяти параллельных операций. Полный серверный набор на локальной `klar_test`: 35/35, включая двукратный seed без дублей и реальные гонки транзакций. Это локальная проверка сценариев, не проверка HTTP опубликованного приложения. Публикация, коммиты и push не выполнялись; production OAuth и работа приложения через Vercel ещё требуют проверки после развёртывания.

Ниже сохранён отчёт предыдущих этапов локальной проверки.

## Перенос на стандартный сервер пользователя

29.10.2026 обе базы Klar перенесены с 55432 на 5432. До изменения .env сохранены pg_dump-копии и исходная конфигурация в игнорируемой .local-postgres/backups. Все строки во всех 52 таблицах каждой базы сверены, исходные базы сохранены. Для приложения создана отдельная роль klar_app без административных прав. Реальный HTTP через Vite проверен для localhost и 127.0.0.1: регистрация 200, me 200, sync 200, logout 200, доступ после logout 401, повторный вход 200. Диагностические аккаунты удалены, пользовательские не затронуты. Причина первоначальной ошибки регистрации — отклонение callbackURL с 127.0.0.1; исправлен точный список локальных origin без расширения production-доступа.

## Что покрывает PostgreSQL-прогон

1. Каталог seed дважды, неизменность старых ID и наличие альтернативного порядка слов.
2. Повторный импорт одного снимка, уникальность batch и старых processed-маркеров.
3. Пересечения двух устройств: max счётчиков, union уникальных наборов, сохранение более нового SRS и отчёты конфликтов статуса/заметки.
4. Все 19 ключей, включая четыре навыка, ошибки, старые достижения, дневной журнал, настройки и устройство голоса.
5. Большой импорт 2000 статусов + 8000 навыков без дублей.
6. Устойчивая идемпотентность событий, запоздавший ответ и отсутствие отката stage/due/last.
7. Запоздавшая ошибка/верный повтор не откатывают recovery и не создают ложное resolved в журнале.
8. Ревизия вместе с происхождением предыдущей правки защищает от случайного совпадения спекулятивных ревизий двух устройств.
9. Preview откатывает всю транзакцию, не меняя прогресс до подтверждения.
10. Старые агрегаты не создают вымышленных попыток; клиентская проекция журнала ограничена 90 днями, экспорт сохраняет полную историю summaries.
11. Изоляция пользователей через реальные подписанные Better Auth sessions; USER по умолчанию, ADMIN guard проверяет текущую роль в БД.
12. Чужой userId/score/correct в изменяющем payload отклоняются; неверный owner-hint старой вкладки даёт 409.
13. Импортированный и офлайн XP сохраняют происхождение, не суммируются повторно и не создают Rating.
14. Вопрос скрыт до старта; посторонний пользователь не получает комнату.
15. Две конкурентные PostgreSQL-транзакции верных ответов дают одну победу и одну пару RatingHistory; реальный SQLSTATE 40001 обрабатывается retry.
16. Повторная отправка ответа не создаёт новую попытку и не повторяет рейтинг; ошибка одного игрока оставляет попытку второму.
17. Casual не начисляет рейтинг; дедлайн и повторный обработчик идемпотентны; reconnect возобновляет sequence.
18. Сервер принимает подготовленный альтернативный порядок предложения.
19. UTC round-trip, полночь Europe/Berlin, переходы DST и завершённый сезон.
20. Экспорт и удаление: приватные данные удаляются, законченная история матчей обезличивается.
21. Реальный локальный HTTP: `/api/progress`, `/api/auth/get-session`, private/no-store, проверка Origin и запрет неавторизованного maintenance.
22. Выполненные шаги мини-урока попадают в дневной журнал ровно один раз.

## Дополнительно проверена парольная авторизация

- Регистрация по email/паролю, библиотечный хеш вместо открытого пароля, USER даже при подмене role.
- Неверный пароль, дубли адресов, некорректный email и короткий пароль отклоняются.
- Вход/выход и реальная cookie через локальный HTTP открывают только свой приватный API.
- При обязательном подтверждении вход запрещён до перехода по настоящей библиотечной ссылке.
- Восстановление одинаково отвечает для неизвестного и существующего email; токен одноразовый, просроченный отклоняется, старые сессии после сброса недействительны.
- Чужой redirect URL отклоняется; автоматическое OAuth-связывание неподтверждённых email отключено.
- SMTP проверен локальным TCP-приёмником. Тестовые письма не доставлялись в интернет; при отсутствии SMTP API явно возвращает 503.

## Границы проверки и будущие этапы

- Настоящий Google/GitHub OAuth roundtrip не выполнен: нужны настройки приложений провайдеров и их серверные секреты. Подписанные сессии и права проверены локально.
- Neon, Vercel deployment, облачные квоты, миграции в облаке и production не проверялись. Ресурсы не создавались, публикации и коммитов не было.
- Полная визуальная проверка аккаунта в браузере не выполнена: локальное управление браузером отключено в настройках Work. RU/UK, стили панели, мобильные ограничения ширины и существующая PWA успешно собраны, но это не заменяет визуальный просмотр.
- Ranked SENTENCE_RACE закрыт до достоверной CEFR-разметки банка предложений. Casual sentence race и ranked/casual word choice имеют тестируемые API.
- Матч MVP содержит один раунд; схема допускает несколько. Полноценные экраны соревнований, приватные приглашения/комнаты и модераторская панель — следующий этап. Роли USER/ADMIN и серверный guard уже реализованы.
- Polling отражает результат с задержкой; это не обещание абсолютной справедливости реакции или защиты от ботов/сговора.
- Бесплатный Vercel cron ежедневный, с неточным временем внутри часа. Активная комната закрывает дедлайн на запросе; брошенные состояния дополнительно закрывает защищённое обслуживание/CLI.

Настройка, таблица всех ключей, ER Mermaid и порядок запуска находятся в `DATABASE-SETUP.md`.
