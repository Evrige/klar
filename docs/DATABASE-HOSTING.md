# PostgreSQL и Prisma для Klar: бесплатный старт с Vercel

Проверено по официальной документации 29 октября 2026 года. Это инструкция и план следующего этапа, а не уже созданная БД. В текущем приложении ещё нет серверной авторизации и Prisma.

## Что где работает

Браузер React/PWA на Vite → HTTPS API на Node.js + TypeScript + Hono в Vercel Functions → Prisma на сервере → PostgreSQL в Neon. Next.js не требуется.

База не загружается в папку dist и не разворачивается внутри статического сайта. Vercel подключает внешний PostgreSQL через Marketplace. React никогда не получает пароль БД. Для синхронизации между устройствами нужен аккаунт и серверный API, одной Prisma schema недостаточно.

## Бесплатный вариант

Рекомендация для старта — Neon Free, подключённый к существующему проекту Klar на Vercel. На дату проверки основная страница Neon указывает 1 GB хранения и 100 CU-hours в месяц на проект; конкретное предложение в Marketplace нужно проверить при создании ресурса, его условия могут отличаться и изменяться. Бесплатный тариф имеет квоты, это не обещание неограниченных онлайн-матчей.

## Порядок действий

### 1. Сначала подготовить backend

Использовать KLAR-DATABASE-PROMPT.md из этой папки. Результатом должны быть server/, api/, prisma/schema.prisma, prisma.config.ts, миграции, seed, авторизация, .env.example и конкретные команды проекта. Пока этих файлов нет, команды миграции ниже выполнять рано.

### 2. Создать PostgreSQL

В панели Vercel открыть проект Klar, раздел Storage/Marketplace, выбрать Neon, создать PostgreSQL на бесплатном плане и подключить к проекту. Выбрать регион рядом с серверными Functions, например регион Германии, если он доступен. Не активировать платные дополнения для первого запуска.

Не путать создание нового аккаунта Neon через native integration с подключением уже существующего аккаунта. После подключения проверить появившиеся переменные окружения: имена могут зависеть от интеграции.

### 3. Получить две строки подключения

В Neon открыть Connect. Нужны:

```dotenv
# Сервер приложения: pooled, в hostname есть -pooler
DATABASE_URL="postgresql://USER:PASSWORD@HOST-pooler/DB?sslmode=require"

# Prisma CLI: direct/unpooled, без -pooler
DATABASE_URL_UNPOOLED="postgresql://USER:PASSWORD@HOST/DB?sslmode=require"
```

Это шаблоны, не рабочие реквизиты. Полные URL копируются из панели, включая параметры. В проекте могут использоваться другие имена, но prisma.config.ts и серверный клиент должны ссылаться на правильные значения. Не публиковать их в чате, GitHub или VITE_*.

До создания .env добавить в .gitignore:

```gitignore
.env
.env.*
!.env.example
```

Dev, Preview и Production должны использовать отдельные базы/ветки. Не выбирать production URL для всех окружений одним действием.

### 4. Подключить Prisma согласованной версии

Официальное руководство Neon сейчас показывает Prisma ORM 7. Для такой реализации:

```powershell
npm install @prisma/client@7 @prisma/adapter-neon@7 dotenv
npm install -D prisma@7 tsx
```

Не устанавливать CLI без версии поверх клиента другого major. Для Prisma 7 подключение CLI задаётся в prisma.config.ts через DATABASE_URL_UNPOOLED, runtime — через Neon adapter с DATABASE_URL. Старый datasource url/directUrl из Prisma 6 сюда не копировать. Дальнейшие шаги зависят от созданной реализации.

[Официальная настройка Prisma + Neon](https://neon.com/docs/guides/prisma)

### 5. Создать и проверить миграции в разработке

После появления schema/config/seed и настройки отдельной dev-базы:

```powershell
npx prisma generate
npx prisma migrate dev --name init_klar
npx prisma db seed
npx prisma studio
```

Seed должен быть заранее настроен в Prisma config и наполнять каталог, а не очищать прогресс. Повторный seed не создаёт дублей. Prisma Studio — инструмент просмотра, не публичная админка для всех пользователей.

### 6. Подготовить production

Сохранить миграции в Git. Убедиться, что все новые файлы server/api/prisma/scripts действительно добавлены в коммит. Не коммитить .env или дамп с персональными данными.

В целевом production-окружении, с отдельно выбранными production URL:

```powershell
npx prisma migrate deploy
npx prisma db seed
```

Не выполнять migrate dev, migrate reset или db push против production как способ обновления. Для первого запуска БД можно сначала подготовить этими командами, затем публиковать приложение. В дальнейшем миграции запускаются отдельным контролируемым шагом CI; preview-деплой не должен менять production-схему.

В Vercel проверить серверные переменные, OAuth callback URL и конфигурацию авторизации. После изменения переменных требуется новый деплой. Команду сборки взять из созданной реализации: генерация Prisma Client должна завершиться до сборки зависимого серверного кода; фронтенд сохраняет Vite output dist. Полная публикация только dist не включает API.

### 7. Проверить приложение

1. Войти в аккаунт и импортировать копию локального прогресса с предварительным просмотром.
2. Убедиться, что повторный импорт не удвоил данные.
3. Открыть аккаунт в другом браузере — прогресс приходит с сервера.
4. Проверить офлайн-практику, восстановление связи и отсутствие данных другого пользователя после выхода.
5. Провести тестовую дуэль: неверный ответ, двойная отправка, одновременные верные ответы, таймаут и переподключение.

## Онлайн-соревнования

По текущей документации Vercel поддерживает native WebSocket в публичной beta на Fluid Compute, включая Hobby. На Hobby одно соединение ограничено 300 секундами, поэтому reconnect/resume нужен даже для правильно работающего сервера. Проверь доступность в своём проекте и текущие квоты перед включением.

Сначала достаточно HTTP API с умеренным polling активной комнаты. Это простой тестовый транспорт, а не гарантия точной синхронности соревнований. Затем можно добавить WebSocket через общий интерфейс. Общее состояние матча и атомарный выбор победителя хранятся в PostgreSQL; память одного инстанса и клиентский секундомер недостаточны. Для малой нагрузки обязательный платный realtime-сервис не нужен, но рост онлайн-аудитории потребует контроля квот и архитектуры доставки между инстансами.

[Документация Vercel о WebSocket, длительности и переподключении](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections)

## Что пока не создано

Эти документы не создают Neon-проект, не содержат секретов и не добавляют настоящую авторизацию/синхронизацию. Следующий шаг — реализация по промпту, затем подключение реквизитов и самостоятельная публикация пользователем.
