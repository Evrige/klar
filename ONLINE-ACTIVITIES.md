# Онлайн-дуэли Klar

Первый рабочий интерфейс находится в разделе «Онлайн-дуэли». Нужны два разных аккаунта, один сервер и одна база PostgreSQL. Соперник — реальный пользователь, боты для заполнения очереди не добавлены.

## Что работает

- Словарный спринт: немецкое слово, четыре перевода, уровни A1/A2/B1, casual или ranked.
- Гонка предложений: одинаковый банк слов с независимыми ID. Подготовленные альтернативы проверяет сервер. Смешанный банк без выдуманных CEFR-меток, пока только casual.
- Серия из 5, 10, 15 или 20 разных заданий. Перед каждым вопросом 3 секунды, на ответ до 30 секунд. Один окончательный ответ на игрока. «На скорость»: первый принятый сервером ответ завершает раунд; правильный даёт балл ответившему, неправильный — сопернику. «На результат»: оба отвечают независимо и получают балл за свой правильный ответ. Победитель определяется суммой баллов серии.
- Окончание по дедлайну, выход с поражением до дедлайна, ничья без правильных ответов. Обновление страницы восстанавливает активный матч и собственную попытку.
- Неоднозначный результат HTTP-запроса повторяется с сохранёнными requestId и answer, без новой попытки. Повтор можно отправить кнопкой. Чужой ответ не возвращается до завершения раунда.
- Сезонный Elo отдельно от учебного XP. Старт 1000; K=40, пока у любого игрока меньше 10 матчей, далее 24. Имена из регистрации появляются в таблице выбранного сезона/режима/уровня после 5 ranked-матчей; это указано перед поиском. Email, userId и учебный прогресс в таблицу не передаются. Старый редактор публичного профиля не требуется.

## Запуск сезона

Требуется миграция 202611010001_duel_series, уже применённая локально и в Neon. Старые матчи сохраняют FIRST_CORRECT и один раунд. Новый интерфейс предлагает SPEED и ACCURACY; их рейтинги разделены, результат начисляется один раз после всей серии. Обязательно загрузить каталог seed и явно открыть сезон в нужной базе:

```powershell
npm run db:season -- klar-2026-11 2026-11-01T00:00:00Z 2026-12-01T00:00:00Z
```

Команда использует выбранное серверное окружение. Сначала проверьте целевую БД. Для локальной проверки нужен сезон, который активен сейчас. Production-сезон автоматически не создаётся; настройка локального сезона не открывает соревнования в Neon.

API: `GET /api/competition/lobby`, `GET/POST/DELETE /api/competition/queue`, `GET /api/competition/match?id=...&after=...`, `POST /api/competition/submit`, `POST /api/competition/leave`, `GET /api/competition/leaderboard?seasonId=...&mode=WORD_CHOICE_RACE&level=A1`. Каждый маршрут требует сессию, записи проверяют Origin; payload строгий. Сервер создаёт токены и вопросы, скрывает вопрос до startsAt, ключ — до завершения. Результат и рейтинг применяются транзакционно.

## Доставка и ограничения

HTTP polling работает только при открытом разделе: очередь раз в 2 секунды, активная комната раз в 1.2 секунды, скрытая вкладка раз в 5 секунд. Курсор sequence позволяет восстановиться после разрыва. Heartbeat-записи не создаются. PostgreSQL хранит состояние, in-memory очереди и отдельного WebSocket-сервера нет; Redis не нужен.

Polling добавляет задержку показа задания и результата; сеть влияет на соревнование. Локальный таймер — подсказка, решение о приёме остаётся серверным. Недоступность сети не превращается в придуманную победу. Общедоступный учебный каталог не защищён от ботов; защита от сговора и продвинутая модерация — дальнейшая работа.

Комнаты по приглашениям, друзья, многопользовательские матчи и WebSocket-транспорт — следующие этапы. Для многопользовательских матчей потребуется отдельный алгоритм рейтинга. В текущем MVP серия рассчитана на двух игроков. Просроченные раунды закрываются по сохранённым дедлайнам; reconnect не продлевает оставленный матч.

## Проверки

`npm run test:server` проверяет реальные гонки PostgreSQL, повторные ответы, рейтинг, дедлайны, изоляцию, отмену одновременно с подбором, reconnect и новые HTTP-маршруты. `npm run build:server` и `node scripts/check-server-build.mjs` проверяют артефакт Vercel без загрузчика TypeScript. Визуальную проверку в двух браузерных сессиях нужно выполнить перед публикацией.


## Открытые игры
Кнопка «Создать игру» создаёт ROOM на 10 минут. Список GET /api/competition/rooms показывает до 100 последних открытых игр: имя, настройки, срок ожидания; email и userId не передаются. Список обновляется раз в 3 секунды только в открытом лобби (скрытая вкладка — 10 секунд). Кнопка присоединения передаёт targetQueueId и точные настройки выбранной игры. Сервер проверяет срок, сезон, статус, владельца и параметры в сериализуемой транзакции; только один соперник может занять место. AUTO остаётся отдельной кнопкой, не забирает ROOM. Устаревшие клиенты совместимы через AUTO по умолчанию. Миграция 202611010002_open_games применена локально и в Neon.

Локальный API запускается через npm run dev:api с tsx watch. Это предотвращает несовпадение версий при изменениях: старый процесс отклонял scoring/questionCount как неизвестные поля (HTTP 400). После перезапуска тот же запрос успешно создал очередь (HTTP 200).


### Разбор ответа в SPEED
Во время трёхсекундной паузы показывается завершённый вопрос: допустимые ответы зелёные, собственный ошибочный выбор красный. Ключ берётся только из раскрытых сервером answers завершённого раунда. Отсчёт использует startsAt следующего раунда и серверное время; после финального ответа — finishedAt + 3 секунды. После отправки клиент сразу перечитывает матч, обычный polling остаётся резервом. Старая HTTP-выборка не заменяет более новый снимок. Проверены границы паузы, восстановление после обновления страницы, последний вопрос и отсутствие раскрытия незавершённого раунда.
